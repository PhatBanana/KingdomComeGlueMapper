# KingdomComeGlueMapper Setup v0.3.8

Experimental Windows x64 prerelease. Download **KingdomComeGlueMapper-Setup-0.3.8-win64.exe**
from the release assets. Python is bundled; Microsoft Edge WebView2 is required.
KCD1 Map requires locally installed KCD1, KCD2 1.5.6 and the official KCD2 Modding
Tools from Steam. No game archives or Warhorse compiler binaries are distributed.

## Changes since 0.3.7

- Correct KCD1-to-KCD2 LOD ratio encoding in both individual render records and
  vegetation group settings. KCD1's byte value 255 means 2.55; KCD2 interprets it
  as 20.0. The converter now preserves the source meaning in KCD2's encoding.
  Native vegetation grid centres and switching radii are also corrected.
- Apply these corrections to fresh setup builds and existing-package upgrades,
  with conversion markers that prevent applying the encoding twice. Terrain
  archive rewrites support directories containing more than 65,535 entries.
- Use native retail-compatible campaign initialization and restore supported
  opening dependencies, objective markers, source dialogue participants,
  proximity speech, quest-item ownership/transfers and inventory icons.
- Include the source-driven tavern and charcoal merchant conversions, their
  supported routines, dialogue, stock and opening-quest interactions.
- Merge [PR #39](https://github.com/SamG-Coder/KingdomComeGlueMapper/pull/39): use
  directory junctions for Data/Localization when a new shader compiler workspace
  is on another drive. This avoids copying the game library. Existing copied
  workspaces are retained; Engine shader repairs and outputs remain private.
- Merge [PR #40](https://github.com/SamG-Coder/KingdomComeGlueMapper/pull/40): stop
  substituting eight source village one-shot emitters with duplicate continuous
  ambience loops. Recipe 33 also migrates existing packages using the source
  control-retirement policy, retaining normal village ambience and shared areas.

## Updating an existing build

Open this executable, choose **Activity → Resume failed setup…**, and select the
original job folder containing **job.json**. A completed job can also be selected.
Completed recipes **3–32** migrate to **33** through the verified staging path.
Compatible completed lighting is retained; these corrections do not require a
full map rebuild. Incomplete or incompatible stages may still need processing.

Close the game before installation. Use **KCD1 Map → Launch mod** to load the
mod-contained shaders. Direct **Install existing packages** does not migrate an
old package. Older running setup executables do not acquire this update automatically.

Quest repairs apply to generated world data; already-consumed dialogue events in
existing saves are not reset. Use a fresh converted New Game to test opening
equipment, rewards and quest initialization. Existing-save travel remains separate.

## Validation and limits

- The full Python 3.14 suite ran **1,315 tests: 1,298 passed and 17 optional
  fixture/backend checks skipped**. Python compilation and all 13 documented
  command-line entry point checks passed.
- The LOD correction has controlled Mod Tools first-approach, stationary-wait and
  retreat evidence for the affected tree, followed by user acceptance of the
  map-wide conversion. This is not exhaustive validation of every roof, model,
  retail configuration or performance scenario. See the
  [LOD investigation](../trosky-lod-streaming-audit.md).
- Review tests exercised a real C:-to-D: directory junction, reuse and safe removal.
  The PR author's full native shader compilation was not repeated for this release.
- Source/native archive comparison confirmed the eight duplicate audio substitutions.
  A read-only migration check against the installed map changed eight audio
  boundaries and removed those eight emitters. It retained 27,541 entities and
  changed only the eight boundary reference lists among those survivors. Repeating the migration was
  byte-identical. Listening evidence is from the PR contributor; no new listening
  acceptance is claimed for the migration.
- The experimental native HLOD exporter, split CGF/CGFM implementation and unrelated
  clothing experiments remain on **Experiment** and are excluded from this release.
- Full campaign conversion, broad NPC/companion behavior, clothing and roof/GI
  fidelity remain unfinished. The bundled OptiX backend targets sm_120 and has CPU
  fallback. No complete build-time or performance guarantee is made.

The attached **self-test.json**, **build-info.json** and **SHA256SUMS.txt** record the
packaged-runtime checks, source commit and installer integrity. Compare the EXE's
`Get-FileHash -Algorithm SHA256` output with SHA256SUMS.txt before installation.
