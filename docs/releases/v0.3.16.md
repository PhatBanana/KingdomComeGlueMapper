# KingdomComeGlueMapper Setup 0.3.16

This prerelease fixes KCD1:MP export stopping with **A visual entity uses
CryEngine's reserved local-player ID/GUID 0x7777**.

The source map's sequential numeric entity IDs can assign 30583 (0x7777) to
ordinary scenery. The reported instance was a generated window light,
`gm_lighting_28757`, with a normal, unrelated GUID. The multiplayer exporter
now assigns a free numeric ID and updates retained links to it after resolving
parent transforms. It preserves the entity's GUID, placement and visual data.
Actual reserved player GUID conflicts and inconsistent links remain errors.

Spawn-point allocation also uses free gaps in the supported ID range instead
of requiring space above the highest source ID.

## Validation

- The installed converted map passed scene preparation with 19,043 retained
  visual entities and only the conflicting light's numeric ID remapped.
- Regression checks cover leading-zero IDs, linked entities, parent transforms,
  deterministic output, a high occupied ID, and preserved player soul records.
- The packaged Windows setup passes its self-test.

This verifies export preparation, not multiplayer gameplay. Player
initialization and two-client gameplay still require an in-game test.

KCD1:MP retains the completed map's lighting and shaders but creates a separate
world snapshot, so it needs additional free disk space. The required amount is
shown by preflight and depends on the source package. No lighting rebake is
needed when reusing a completed map.

See the [multiplayer setup guide](../kcd1-mp-setup.md) for supported versions,
configuration and launch instructions. All 0.3.15 features remain included.
